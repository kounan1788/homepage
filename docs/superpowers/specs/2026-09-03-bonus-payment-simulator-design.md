# ノレタ ボーナス払いシミュレーター 設計

作成日: 2026-09-03

## 目的

ノレタの全21車種ページで、「ボーナス払い（年2回）を上乗せすると分割手数料がいくら安くなるか」を
その場で確認できるようにする。

## 確定した前提

| 項目 | 決定 |
|---|---|
| 実質年率 | 3.9%（サイト表記の3.2%も3.9%に統一済み） |
| 支払回数 | 全車種一律 36回 |
| ボーナス回数 | 年2回（6か月ごと＝計6回） |
| スライダー範囲 | 0円 〜 200,000円（ボーナス**1回あたり**の上乗せ額・10,000円刻み） |
| 計算方式 | 残債方式（元利均等）。月々の額は変えず、ボーナス月に繰上返済を上乗せする |
| 元金 | 車種ごとに `carLoanPrincipals` に登録。現在は概算のサンプル値 |
| 表示内容 | 分割手数料の軽減額のみ |

## なぜこの計算方式なのか

検討の過程で、以下の3案を実数で比較した（ハスラー・元金175万円・ボーナス1回20万円）。

| 案 | 月々 | 分割手数料 |
|---|---|---|
| A. ボーナス併用払い（36回固定・元金を月々とボーナスに振り分け） | 51,589 → 18,526円 | 107,204 → 116,936円（**増える**） |
| B. 月々据え置き＋ボーナス月に追加返済 ← **採用** | 51,589円（変わらない） | 107,204 → 70,426円（−36,778円） |
| E. ボーナス分を元金から差し引く | 51,589 → 16,214円 | 107,204 → 33,704円（−73,500円） |

案Aで手数料が増えるのは実装の誤りではなく、毎月払う代わりに6か月ごとにまとめて払うと
その間の残高が高いままになるため。金融的に正しい挙動である。

案Bを採用した。月々の額が変わらないため表示は手数料の軽減額だけで足り、
実際の繰上返済と同じ考え方なので数字も信頼できる。

## アーキテクチャ

### lib/carPrices.ts（変更）

既存の `carBasePrices`（月額）はそのまま維持し、以下を追加した。

- `ANNUAL_INTEREST_RATE = 0.039` … 金利の単一の情報源
- `LOAN_PAYMENTS = 36` … 支払回数（全車種共通）
- `BONUS_INTERVAL_MONTHS = 6` … ボーナス月の間隔
- `carLoanPrincipals` … 車種別の元金（サンプル値）

### lib/loanCalculator.ts（新規）

副作用のない純粋関数のみ。公開しているのは1つだけ。

- `calcInterestReduction(principal, bonusPerTime)` → 軽減額（円）

内部では、まずボーナスなしで36回完済する月額を二分探索で求め、
その月額のままボーナス月に上乗せした場合の総支払額と比較する。

### components/BonusPaymentSimulator.tsx（新規）

Props は `principal` のみ。21車種ページで共通利用する。
スライダーと軽減額の表示だけを持つ。

### 各車種ページ（21ファイル・変更）

オプションセクションの直前に `<BonusPaymentSimulator />` を差し込んだ。
既存の見積もり計算には一切触れていない。

### app/noreta/ClientPage.tsx（変更）

金利の「3.2%」表記を3.9%に修正（4か所）。
「ボーナス払いなし」の訴求は、案Bではボーナス払いが任意の上乗せであり
矛盾しないため変更していない。

## 既知の制約

`carLoanPrincipals` は車両価格の概算サンプル値であり、現在の月額表示とは整合していない。
たとえばハスラーは月額27,000円×36回＝97.2万円で、サンプル元金175万円には届かない。
ノレタが3年で完済ではなく残債が残る自由返済型であることによる差と考えられる。

軽減額は元金の大小にあまり左右されない（ボーナス額でほぼ決まる）ため、
サンプル値のままでも表示は破綻しないが、正確な数字を出すには実際の分割対象元金への
差し替えが必要である。
